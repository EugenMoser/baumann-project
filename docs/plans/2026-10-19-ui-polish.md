# UI polish (feature 4a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The public catalog gets the approved "datasheet" look (tokens, fonts, shell, home, product page, other pages), the home page and product page show the new derived values, and new products in the admin start as drafts.

**Architecture:** Presentation changes in `app/` and `components/` on top of the existing data layer. New derived values are pure functions in `lib/catalog/` (unit-tested) fed by the existing catalog client under RLS; two read additions: one overview query for home and `/produkte`, one thumbnail query after a search. Customer copy lives in `config/branding.ts` so revocation removes it.

**Tech Stack:** Next.js 16.3 App Router, React 19.2, TypeScript strict, Tailwind 4 (`@theme` tokens), `next/font/google`, Supabase (`@supabase/ssr`), Vitest + Testing Library, Playwright + axe.

**Spec:** `docs/specs/2026-10-19-ui-polish-design.md` (FR-1 … FR-9, D1 … D9). Read it before any task. The controller hands every implementer the approved HTML mockup (direction A); where mockup and spec differ, the spec wins (no millimetre grid, no dimension lines, no image in the home hero).

## Global Constraints

- Code, identifiers, comments, commit messages: English. UI texts: German, exactly as written in this plan or the spec.
- TypeScript `strict`, no `any`; `Result` from `lib/result.ts` for fallible data access; Zod for config parsing.
- Tokens (D1), names unchanged, values: `paper #ffffff`, `surface #f5f4f1`, `ink #14171a`, `muted #5d656e`, `line #dcddd9`, `accent #d4500f`, `accent-strong #b5440d`. `accent` is never a text colour.
- Fonts: Instrument Sans (400, 500, 600, 700) as `--font-sans`, IBM Plex Mono (400, 500, 600) as `--font-mono`, both via `next/font/google`; Geist removed.
- Article, order and certificate numbers always `font-mono`.
- Transitions only for colour/border on hover and focus, ≤ 150 ms, wrapped in `motion-safe:`.
- Focus ring stays `2px solid accent` with offset (global `:focus-visible` rule).
- Demo banner texts and links, `noindex` meta, `X-Robots-Tag` and `robots.txt` never change.
- No new dependencies. No DB migration. No change to `search_catalog`, routes, caching (`revalidate`, `connection()`), or JSON-LD.
- Next.js 16: read `node_modules/next/dist/docs/` before using an API not yet used in this repo (`next/font/google` options, `usePathname` in a client component under a server layout).
- Commands: `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm db:test` (local stack running), `pnpm build`, `pnpm e2e` (see CLAUDE.md for the build env).
- Commits: Conventional Commits; WIP commits on `feat/ui-polish` are fine. Never commit images.

## Review Focus

1. **Product whose articles carry no attributes** (e.g. seeded `testabdeckung` with only a text attribute on one article, or none) → table shows no empty attribute columns, spec list shows only material and article count. Tests in Task 7.
2. **One attribute with mixed numeric and text values across articles** → column left-aligned as text, summary uses the text rule. Test in Task 7.
3. **Colour selected that the first article does not have** → order box shows the first article that has it, else the first article's fallback; the inquiry link carries the same number. Test in Task 7.
4. **Category without published products or without any thumbnail** → register row still links, shows "0 Produktgruppen" / no thumbnails; intro text without a sentence end or with a very long first sentence → subline cut at a word boundary with "…". Tests in Task 4.
5. **Long product names and numbers like `99211/80` at 360 px** → no page-level horizontal scroll; only the article table region scrolls. Test in Task 11 (all pages) with `break-words` on titles.
